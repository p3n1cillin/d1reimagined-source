# Served fixtures for PS4 build 56578

What the project's servers hand the 56578 client during a lab run: the Guardian, the mission schedule
and the post-game screens. None of it is a game file. Each file is an object the server encodes and
sends, or a list the activity host reads, built by the project's own tools (`d1-oracle`,
`d1-inventory-renumber.py`, `d1-agr-steps.py`, `d1-winguest.py sensor-clients`) from the maintainer's
owned copy. The scripts find this folder through `D1_FIXTURES` (default: here; see
`tools/ps4_setup/d1paths.py`).

### `worlds/`: the generated world tables

Tab-separated, one `# GENERATED` line, then a header. `-` is empty; lists are comma-separated; hashes
are `0x` and eight hex digits. Regenerate with `python tools/ps4_setup/d1-world-table.py --packages
<owned packages> --hosts <d1-srcp.py hosts TSV>` (Node, and Blam Network's tiger built, under
`D1_TIGER`). [notes/ps4-56578-worlds-2026-11-05.md](../../../notes/ps4-56578-worlds-2026-11-05.md)
has the method and the coverage of each activity.

| File | Row | Columns |
|---|---|---|
| `worlds.tsv` | a world (`<world>:scenario_client`) | `world`, `scenario_tag`, `family` (+0x08, FNV-1 of the name), `private_checksum` (+0x0C, the value rung 33 compares), `public_checksum`, `bubble_count`, `chosen` (bubbles with a valid state), `public_slice_sets`, `destination`, `static_world` (the descriptors' world hashes) |
| `slice-sets.tsv` | a slice set, `8 * bubble + state` | `world`, `slice_set`, `bubble`, `valid`, `public` (needs a public session), `region_hash`, `descriptor`, `static_world`, `static_bubble`, then the bundle tags the client loads: `global`, `authoritative`, `private` |
| `bundles.tsv` | a bundle tag's lookup group | `bundle_tag`, `group` (the sensor group, FNV-1 of the bundle name), `lookup_bubble` (-1 = every bubble), `clients`: `TYPE:INDEX:AB` per sensor client, A and B = 1 when the row has an auth or sense value type |
| `insertion-points.tsv` | a static world's bubble | `static_world`, `bubble`, `insertion_points`: `NAME_HASH:COUNT` per spawn-point name (`0x2ea8fb98` = `default`), `?` where unreadable |
| `activities.tsv` | an activity index | `index`, `hash`, `name` and `type` (the manifest's), `world`, `start_region` (slice set), `start_source` (`capture`, `capture of N`, `2014 start bubble`, `only slice set`, `stand-in: first private slice set`), `start_public`, `private_start`, `sensor_group` (the group holding the lifetime record), `status` (`cross-checked`, `generated`, `missing evidence`), `evidence` |

A slice set's sensor-client list is every client of its bundles whose `lookup_bubble` is -1 or the
slice set's bubble, in global, authoritative, private order, each `(group, type, index)` once.
`d1-world-table.py --sensor-list WORLD:SLICE_SET` prints it in the `mission/` list format.

[incidents-56578.tsv](incidents-56578.tsv) contains the complete client incident index,
name hash, known name, payload selector and auxiliary values.
[incidents-51539-to-56578.tsv](incidents-51539-to-56578.tsv) translates the legacy indices by
name hash, leaving absent targets blank. These are offline identity facts for host and script
tooling, not incident bodies. Regenerate with `tools/ps4_setup/d1_incidents.py`; see the
[catalogue note](../../../notes/ps4-56578-incident-catalog-2026-11-05.md).

The Guardian is a Titan Striker. Every peer card carries the Striker's ability rows and perks, and
both subclass items name grid 132 with its default nodes (`tools/ps4_setup/d1-talent-grid.py 132`,
written with `d1-character-fixup.py`; issue #134). Without them there is no grenade, melee or super.

Every profile and peer card also sets the wear-helmet flag (customization block `0x8080181A`, the
2-bit field at `+0x2C`; `d1-character-fixup.py --helmet`). With it clear, the Guardian had no head in
the Tower (issue #128); run sense77 (31 October) served it set and the helmet showed.

The three post-game profiles (`postgame/profile-active164-xp0`, `-xp900`, `arcadia-profile-xp900-owned`)
carry the gear the Guardian leaves the mission with. That is the tutorial inventory's subclass,
armour, Ghost and vehicle, plus the granted Khvostov, each in its bucket's slot and in the equipped
array (`d1-character-fixup.py --item`; notes/ps4-56578-equip-2026-11-01.md). Without it the character
screen after the mission was empty. The items are the ones `characters/inventory-tutorial` and the
rifle grant serve.

Every served profile (`characters/`, `grants/`, `postgame/`) has its unused stat-override entries
marked absent (key `0xFF`; `tools/ps4_setup/d1-profile-override-tail.py`, 7 November 2026). Written
as (0, 0) they reset the effective rating to 0 (notes/ps4-56578-content-gates-2026-11-07.md).

Every served peer card (`f0t1-*.bin`) and profile carries a coherent look (identity and
customization; `tools/ps4_setup/d1-fixture-look.py`, 7 November 2026). They had race 0, gender 0,
class 1 (a Hunter, on a Titan with Titan gear) and an all-zero customization, and the character
screen drew no Guardian. The look written is a stand-in: the client's own default Exo male Titan
from its character creation (run new1).

The tutorial profiles carry the same gear during the mission. `profile-tutorial-t.bin` (served at
boot) holds the subclass, armour, Ghost and vehicle. `grants/profile-tutorial-th.bin` (pushed with
the Breach rifle) adds the Khvostov. The character screen at the start of the mission (run sense86)
shows the armour, Ghost and subclass, with the weapon slots locked until the rifle.

The defaults of `lab/tower-route/ending-run.ps1` serve what run sense73 (31 October 2026) served,
except for the account (sense73's put Legendary Marks in Silver's slot) and the post-game gear above. Files named `*.draft.*` are lab drafts, kept as they were served.
