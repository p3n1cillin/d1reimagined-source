## 1. What a "run" is, how runs are detected, how they are issued

The donor has three run mechanisms. Only the GPU-CP run executor is the active fast path.

**A. GPU-CP run executor** (SHADPS4_D1_GPU_CP=1, executor "runs", host sequences on, unified on; README.md:151-156).
- **Two conditions for consecutive draws.**
  - Same range. A range is one attachment hash: `liverpool->attachment_state_hash ^ HashMix(bound color mask)`. A new hash closes the range and opens another [C] vk_rasterizer_gpu_cp.cpp:355-360.
  - Same run key. The key is XXH3 of: pipeline pointer, index chunk VkBuffer, index type | indexed<<8 | stage_present<<16, `key_state_hash`, `dynamic_state_hash`, primitive type [C] :1482-1488. The run continues only while `gpu_run_open && gpu_runs.back().key == run_key` [C] :1489. It is a strict comparison with the immediately preceding record, so there is no reordering.
- **What else closes a run or range.**
  - A refused or unplaceable draw. It goes to the classic path in a CPU sub-range, after the range's earlier draws [C] :383-401.
  - Tessellation or geometry stages (`stage_enable != 0`), or rect/quad lists when they are off [C] :361-377, :860-866.
  - A draw that reads a pending DMA destination: CloseRange(Dma), then the DMA is flushed [C] :349-354.
  - Record ring full: the rest of the frame goes to the CPU [C] :403-409.
- **Detection is a hash compare, not dirty bits.** `key_state_hash` and `dynamic_state_hash` are register-derived hashes kept by Liverpool. The "observed-writer contract" belongs to stage versions (section 3), not to run detection.
- **Issue.**
  - Per draw, the host writes a 64-byte DrawHeader plus the stage blocks into the record's slot [C] :1459-1470.
  - It writes the per-frame address table: `tables[stage*MaxRecordsPerFrame + ordinal] = block address` [C] :1473-1480.
  - It writes the args `{num_indices, instances, first_index, vertex_offset, instance_offset}` [C] :1457-1458.
  - Per run, FlushGpuRuns:
    - applies the dynamic-state delta (ApplyDesired, then commit) [C] :2913-2927;
    - sets push block flags `PushRunFlag|PushRunTableFlag`, with `stage_block[l] = TableAddress(l, run.first)` [C] :2929-2937;
    - calls BindResources, bindPipeline (only if changed) and bindIndexBuffer (only if changed) [C] :2943-2959;
    - makes one `drawIndexedIndirect(seq buffer, first*SeqStride+SeqDrawOffset, count, SeqStride)` [C] :2960-2961.
  - Non-indexed draws run over an identity index buffer of 4M entries [C] vk_gpu_cp.h:39, vk_rasterizer_gpu_cp.cpp:1392.
  - Capacity is 16,384 records a frame [C] vk_gpu_cp.h:36.
  - GPU_CP_VRAM_TABLES (default on) puts the address table in the ReBAR heap and the identity index buffer in device memory, not host memory [C] vk_gpu_cp.h:66-67, vk_gpu_cp.cpp:101-106.

**B. Resolver single runs** (SHADPS4_D1_RESOLVER).
- A run is records in consecutive ring slots with the same `run_key`. The key is XXH3 of key_state_hash, dynamic_state_hash, attachment_hash, index type|indexed, pipeline, index chunk [C] vk_rasterizer_resolver.cpp:1409-1414.

## (1) How the fork imports guest RAM as Vulkan memory
- **Mechanism:** it uses VK_EXT_external_memory_host on the emulator's single canonical physical backing. Imports are keyed by physical address, so one import covers every guest alias of a page. Read-only acquisitions then return a view over the guest's own bytes (shadPS4 `src/video_core/buffer_cache/uma_import.h:31-42`; `documents/d1/rendering.md:23-30`).
- **Granularity:** fixed 64 MiB chunks (`uma_import.h:319`), keyed by `phys / ChunkSize` (`uma_import.cpp:273-295`). The last chunk is clipped to the end of the backing (`:281-285`). A range that crosses a chunk boundary falls back to the mirror (`:208-212`).
- **Alignment:** the host pointer and the size must both be multiples of `MinImportedHostPointerAlignment`, otherwise the range takes the mirror (`uma_import.cpp:300-308`).
- **Memory type:** it must be in both the pointer's and the buffer's type bits and be HOST_VISIBLE|HOST_COHERENT. A noncoherent type would need cache maintenance that Vulkan has no portable API for (`:552-586`).
- **Allocation:** allocated with the DEVICE_ADDRESS flag (`:588-600`). The buffer usage covers uniform, storage, vertex, index, indirect, transfer src/dst and device address, and must match the capability query exactly (`:70-78`).
- **When it happens:**
  - lazily, on the first `Locate` of a chunk (`:231`);
  - up front with `ImportAll(total_bytes)` (`:524-545`). The research doc records 132 chunks, 8,448 MiB, imported up front (`documents/perf/RESEARCH-20260911-where-the-frame-waits.md:193`);
  - private host ranges (module image, stacks) go in through `ImportForeign`, keyed by guest VA (`uma_import.h:130-134`; `.cpp:355-380`).
- **Write-watched mappings:**
  - With `SHADPS4_D1_WRITE_WATCH=1`, every all-GARLIC direct mapping of at least 64 MiB is backed by its own `VirtualAlloc2 + MEM_WRITE_WATCH` commit instead of a view of the backing (`src/core/d1_write_watch.h:6-15`).
  - On Linux it is instead a private anonymous MAP_FIXED mapping with MADV_NOHUGEPAGE, tracked by soft-dirty bits (`:17-24`).
  - Each such mapping is imported as its own host-pointer pieces at map time (`ImportWatchedPieces`, `uma_import.cpp:620-634`). `Locate` narrows its translation to that mapping (`:152-157`, `:169-205`).
- **Self-test:** the first acquisition imports the chunk, has the GPU copy guest bytes out of it, and compares them with the host pointer. A failure disables the backend for the session (`uma_import.h:60-64`; `.cpp:214-229`, `:1095-`).

## (2) How a buffer bound by guest address resolves to an imported offset, and what the resident copies are
- **Read path:** `TryAcquireRead` → `Locate` (`uma_import.cpp:116-250`):
  - It first consumes a pending translation flush, which guest map/unmap events raise (`:127-135`; `.h:308-316`).
  - It translates VA to physical through a 1024-slot cache keyed by `addr>>16`. A miss takes the MemoryManager's `ResolveDirectSpan` (`:137-160`).
  - It refuses ranges with more than one alias (`:161-168`), because CPU-dirty tracking is per virtual address.
  - It returns `{chunk shim Buffer, phys - chunk.phys_base}`.
  - It records a lease at `scheduler.CurrentTick()` (`:244-249`).
- **Address-only path** (`ResolveDeviceSpan` / `ResolveDirect`, `:403-522`): returns a device address. A per-thread cache keyed by 2 MiB granule and validated by span bounds and `map_epoch` replaced a 16 KiB-page cache that missed several times per draw. The measured load was 1.32 M resolutions a second (`:470-475`).
- **GPU writes into guest RAM** (`TryAcquireDirectWrite`, `:252-271`): the write lands in the host piece and accepts multiple aliases.
- **Resident copies** (`SHADPS4_D1_RESIDENT=1`, which requires write-watch) (`uma_import.h:136-152`; `documents/perf/HANDOFF-20260912-resident-garlic.md:59-96`):
  - Each 64 MiB watched piece the GPU reads gets a device-local copy.
  - **Creation:** only on the CP thread, on a real use, and only within budget (`ResidentServe`, `.cpp:677-799`). Budget = VK_EXT_memory_budget heap budget − current usage − a reserve (`RESIDENT_RESERVE_MIB`, default 3072), with an optional hard cap `RESIDENT_BUDGET_MIB` (`:636-675`).
  - **Fill and serving:** a whole-piece copy is queued and recorded at the next `FlushResidentCopies` (barrier, copies, barrier). The piece is served once that copy is recorded: lock-free slot tables plus a map-epoch bump that republishes the page table (`:901-974`).
  - **Dirty runs:** each write-watch sweep's dirty runs become range copies from the host piece (`ResidentDirty`, `:801-830`).
- **Write-watch tracking:** `GetWriteWatch(RESET)` over the registered spans (`d1_write_watch.h:30-41`).
  - The sweeper thread publishes completed sweeps to a bounded ring.
  - Before consuming a top-level submission, the CP applies every completed sweep in order and waits only for a sweep that began after that submission was published (`BeforeSubmission`, `d1_write_watch.cpp:923-1032`).
  - Coverage is committed only from sweeps in which every query succeeded (`:1000-1004`).
- **Demotion:** `ResidentMaintain` runs about once a second. It demotes up to 4 pieces per pass, image-upload-only pieces first, then the least recently read. A demoted piece's memory waits in a graveyard until `scheduler.IsFree(tick)` (`uma_import.cpp:1019-1083`). On unmap, `ResidentRelease` demotes (`:1085-1093`).

## (3) Hazards the fork handled
- **CPU writes after GPU reads:**
  - The lease records the newest tick that may read imported memory. Identity transitions (unmap) wait on that tick (`uma_import.h:67-77`, `:245-258`).
  - The lease is deliberately lock-free and blind to ranges. Unmap runs inside the memory manager's locks; resolving the range there would deadlock the guest thread and stall the CP, and it produced an nvlddmkm 0x141 TDR (`:250-255`).
  - Chunks live for the whole process because the canonical backing outlives every guest mapping (`:44-46`).
- **Fences:**
  - Writing GPU results into guest memory needs fence labels written at GPU completion (stage 3). With labels written at parse time, the guest frees and reuses memory before a recorded write executes (`rendering.md:41-46`, `:190-192`).
  - `SHADPS4_D1_FENCE_EARLY`, which writes labels at parse time, is kept as an experiment only (`documents/d1/README.md:104`).
- **Coherence:**
  - Only HOST_COHERENT types are accepted (above).
  - Stale translations after a remap serve old physical pages and produced guest null-pointer faults, so a flush runs at every entry point (`uma_import.h:308-316`).
  - **Page protection breaks the GPU mapping (measured):** a protection change on pages of an imported host allocation breaks it, so watched spans are never protected and `Protect` refuses (`HANDOFF-resident-garlic.md:50-52`).
- **GPU writes and the mirror:**
  - GPU writes such as DMA land in the host piece and are then refreshed into the resident piece (`uma_import.h:175-199`). The reason, measured: the engine streams shaders and geometry into GARLIC by DMA from ONION staging. A DMA that landed only in VRAM left the CP's copy unwritten ("Shader binary info not found", `HANDOFF-resident-garlic.md:74-82`).
  - Stores by address still go to the resident piece (an accepted risk, `:80-82`).
  - When image uploads read the mirror on the GPU timeline, the result was glyph garbage and vanishing bodies. That is off since build 15 and uploads stage from guest RAM (`rendering.md:79-85`; `README.md:118`).
- **Why resident copies exist:** on the discrete GPU every warp's dependent load paid a PCIe round trip, since host memory is not GPU-cached (`RESEARCH-20260911-where-the-frame-waits.md:31-34`, `:78-86`).
- **Resident copies are refused on UNIFIED (integrated) memory,** where they would duplicate guest bytes in the same DRAM (`d1_write_watch.cpp:658-663`; `src/video_core/memory_topology.h:17-20`, `:62-63`). So on this APU the fork's own policy is import only, with no resident copies.

## (5) Port onto bbport
**What bbport has today**
- No host import exists. Grep of `buffer_cache.cpp/.h` finds no `ImportMemory`, `external_memory` or `HostPointer`, and no `CopySparseSerial`.
- The buffer cache is upstream's sparse-arena model:
  - 4 GiB sparse arenas indexed by guest VA (`buffer_cache.h:40-44`, `:168-169`);
  - `EnsureResident` allocates device-local `vk::DeviceMemory` for the gap blocks, queues `SparseMemoryBind`s and writes the BDA page table (`buffer_cache.cpp:448-503`);
  - the arena memory type is the first DEVICE_LOCAL type in the sparse buffer's type bits (`:63-84`).
- `ObtainBuffer` (`buffer_cache.cpp:287-339`) works like this:
  - read-only ranges of 16 KiB or less are copied into the stream buffer on copy threads (`:295-321`);
  - everything else goes through `EnsureResident` and `SynchronizeMemory` (tracker-driven uploads, `:505-525`) and returns `{arena, arena->Offset(addr)}`.
- GPU-modified readback is `DownloadMemory` with `scheduler.Finish()` (`:165-203`).
- **Callers** (`vk_rasterizer.cpp`): vertex ranges `:1896`, index buffer `:1954`, buffers `:2225`, indirect `:1308/1314`, DMA `:3158/3179/3185`.

**Where the import plugs in (design)**
- **B1, fork-proven:** an import backend called at the top of `ObtainBuffer`, before the stream-copy branch at `:295`:
  - if the range lies in an imported class, return `{chunk shim, phys - chunk_phys}`;
  - this skips `EnsureResident`, `SynchronizeMemory` and the 16 KiB stream copy;
  - the import is of the backing view (`backing_base + phys`), not the guest-VA view. On Linux an `mprotect` of a guest-VA view does not touch the backing VMA's PTEs. This is design reasoning, not measured.
  - The BDA page table must be republished for imported blocks, as the fork did with `RepublishBdaPages`.
- **B2, cheaper if valid:** in `EnsureResident`, sparse-bind the imported `DeviceMemory` at the arena offset instead of allocating device-local memory. `ObtainBuffer` and the BDA table then stay unchanged. Unknown: whether RADV's sparse buffers accept the host-pointer memory types (`reqs.memoryTypeBits` at `:70-74`). This needs a probe.

**Per class, static GARLIC first**
- The class comes from the runtime: `direct_allocate` stores the type per block (`runtime_memory.c:286`) and `direct_memory_type` exposes it (`:531-540`). Type 3 is GARLIC (`BIG-IDEAS:36-38`).
- From the fork's census (`BIG-IDEAS:138-146`):
  - vertex fetch and indices are 100% GARLIC, so the first class is meshes and indices;
  - constants are 99% ONION and stay on the stream copy.
- Imported pages must be excluded from:
  - `runtime_memory_gpu_protect` (`runtime_memory.c:725-736`) and the fault window;
  - the memory tracker's upload ranges.
- DMA into GARLIC must write the import directly (`rasterizer.CopyBuffer` → `ObtainBuffer(dst, true)`, `vk_rasterizer.cpp:3158`). Otherwise the guest's copy is stale, which is the fork's "Shader binary info not found" failure (`HANDOFF:77-80`).
- Open risk, not read: the engine defrags GPU resources (`defrag_handle_relocated_gpu_entry` `0xdcc10`, `BIG-IDEAS:59`). Whether it moves them by CPU or by DMA is unknown.

**"Fences honest" in bbport's scheduler, concretely**
- **Today, fences are written when they are recorded, not when the GPU finishes:**
  - EOP with the Stage B path: `SignalAfterHostCopies`, after the host copies queued before it (`liverpool.cpp:274-277`);
  - otherwise: `WaitHostCopies`, then `WaitDeferredSignals`, then a direct write (`:279-282`);
  - EOS, WriteData and flip follow the same rule (`:320-349`).
  - The guarantee is only "the bytes were copied out before the guest learns the fence" (`vk_scheduler.h:792-818`). With in-place reads there is no copy, so that guarantee is void.
- **Honest version:**
  - When the EOP is reached on the recording thread, take `T = scheduler.CurrentTick()`.
  - Ensure that tick is submitted soon (a flush), since otherwise the guest waits for the next natural submit.
  - Write the label once `IsFree(T)` (`vk_scheduler.h:839-845`), for example through `DeferPriorityOperation` (`:860-868`), which runs on another thread when the GPU reaches the tick.
  - Keep labels in order across EOP, EOS, WriteData and flip with a per-queue completion queue that `WaitDeferredSignals` drains. Ordering matters because of the heap-corruption hazard in `:814-818`.
- **Gate it per fence:** take the honest path only if an imported read was served since the previous fence, using a flag set by the import path (the analogue of the fork's `BumpLease`). Otherwise keep today's path, so classes that are not imported pay nothing.
- **Unmap:** `hook_unmap` already drains queued draws before the memory changes (`runtime_memory.c:84-88`). It must additionally wait for `IsFree(newest_import_lease_tick)`.

**Producing the version check** (REV2 §7.1: `PLAN-TO-60-REV2-20261005.md:190-200`)
- **First hash, at decode:** on the engine thread at the emit hook (the PreparedDraw keyed by emit serial that steps 2-4 are landing), hash the first and last N bytes of each range the record names: the index record's base, type and count, and the vertex handles plus offsets. Store the hash in the record.
- **Second hash, by class:**
  - copied classes: the recording thread hashes when it copies (REV2 as written);
  - in-place classes: the CPU never reads at record time, so hash in the honest-fence completion callback, after `IsFree(T)` and before the label is written.
- **What a mismatch means:** the guest rewrote the bytes while the GPU work was in flight, which means our fence was early.
- **Exclusions:** report apart any range with a pending in-stream DMA or fill.
- **Positive control:** force record-time fences for the imported class; the counter must fire.
- Implementation status in `native/patches/` was not read and is unknown.

## (6) Guest memory layout on the seat (`d1port/src/runtime_memory.c`)
- **Backing:**
  - one `memfd_create("bb-guest-memory")` sized POOL_SIZE + 1 GiB of flexible space (`:105-112`);
  - POOL_SIZE defaults to 5056 MiB; `BB_DMEM_MB` takes values up to 16384 (`:20-31`);
  - a second whole view, `mmap(PROT_RW, MAP_SHARED|MAP_NORESERVE)`, is `backing_base`, used for host writes that bypass guest or GPU protection (`:75`, `:109-111`, `:661-673`).
- **Direct memory:**
  - `direct_allocate` hands out physical offsets aligned to the requested alignment (16 KiB minimum, power of two) from a 4096-entry block table and records the type (`:263-291`);
  - **GARLIC, ONION and the other types are not distinguished on the host:** the type is stored and queryable but changes no host mapping flag;
  - `place()` maps a direct or flexible range with `mmap(addr, size, prot, MAP_SHARED|MAP_FIXED, pool_fd, phys)`. Reservations are `MAP_PRIVATE|MAP_ANONYMOUS|MAP_NORESERVE|MAP_FIXED` with PROT_NONE (`:225-245`).
- **No huge pages:** there is no `madvise` or MADV_HUGEPAGE anywhere in the file (grep).
- **Page size and VA range:** guest page 16 KiB (`:34`); guest VA between `0x10_0000_0000` and `0xfc_0000_0000`, below 1 TiB because descriptors encode 40-bit addresses (`:4-5`, `:35-36`).
- **GPU hooks:** map, unmap and invalidate are queued and run in order outside the table lock, under the topology lock (`:78-137`, `:648-659`). GPU page tracking uses `mprotect` on the guest view (`:725-736`).
- **Unknowns that need a seat probe:**

## (1) The key bbport would look up a precompiled SPIR-V under

**Program identity is not a hash bbport computes.** It is the 64-bit `shader_hash` from the `OrbShdr` footer that the PSSL compiler embeds in the binary [C]:
- `GetParams` gives `.hash = bininfo.shader_hash` (regs_shader.h:243-250).
- `BinaryInfo{signature "OrbShdr", ..., u64 shader_hash; u32 crc32}` (regs_shader.h:16-35).
- The footer is found by a token jump or by scanning up to 0x4000 dwords (regs_shader.h:224-240).
- No bytes are hashed at runtime. `Info::pgm_hash` is this value (GetShaderName and RegisterShaderBinary use `info.pgm_hash`, vk_pipeline_cache.cpp:919, 939).

**A variant (permutation) is selected by `Shader::StageSpecialization` equality** (specialization.h:82-249) [C]. The comparison covers:
- `runtime_info`, compared through `RuntimeInfo::operator==` (runtime_info.h:298-301):
  - `props`: fp denorm and round modes, num_user_data, num_input_vgprs, num_allocated_vgprs (runtime_info.h:265-274).
  - The software-stage union, e.g. VS step_rate_0/1, vertex/instance sgpr offsets, tess_emulated_primitive (runtime_info.h:71-76).
  - The hardware-stage union:
    - VS: num_outputs, outputs map, emulate_depth_negative_one_to_one, clip_disable, user_clip_plane_mask, **motion_vectors** (runtime_info.h:108-115).
    - FS: en/addr flags, PS inputs, **color_buffers (format, number format, conversion, export format, swizzle)**, z_export_format, num_samples, mrtz_mask, dual-source, clip emulation, **motion_vectors** (runtime_info.h:202-244).
- `fetch_shader_data`, plus per-attribute `vs_attribs` (divisor, number class, dst_select) (specialization.h:100-117).
- Per bound resource:
  - Buffer: stride, formatted, swizzle (specialization.h:119-134).
  - Image: view type, integer, storage, cube, srgb, `is_d1_shadow_helper`, conversion, num_bindings (specialization.h:135-149).
  - Fmask: width and height. Sampler: unnormalized, degamma (specialization.h:150-159).
- `start`: the Vulkan binding counters carried over from the previous stages (specialization.h:94, 219-229).

**Inputs to the compiler beyond the GCN bytes** [C]:
- `TranslateProgram(code, pools, Info&, RuntimeInfo&, const Profile&)` (recompiler.h:30-32). `EmitSPIRV(profile, runtime_info, ir, binding)` (vk_pipeline_cache.cpp:924-925).
- `Profile` is built once per device from Vulkan features. It includes subgroup_size, the int8/16/64 and fp16/64 support flags, float-control modes, barycentrics, `needs_*` driver quirks, and `BB_INTERP_INT_FIX` (vk_pipeline_cache.cpp:288-349). Passes that read it are at recompiler.cpp:94, 109-146.

**The variant index is not a content key.** `perm_idx` is the order in which a variant was first seen in this process (`program->modules.size()`, vk_pipeline_cache.cpp:1032). The stable name is `HashCombine(pgm_hash, perm_idx)` (lines 1006, 1033). The graphics pipeline key holds these per-stage `stage_hashes` (lines 808-809).

**Consequence [I]:** a precompiled lookup has to be keyed by `(shader_hash, digest of the serialized StageSpecialization, Profile digest, translator version)`. A key of `(hash, perm_idx)` fails because the index depends on traversal order. `StageSpecialization::Serialize` already writes every field above (vk_pipeline_serialization.cpp:459-479), so its bytes can serve as the digest input.

**The stage's `Info` is needed too, not only SPIR-V.** For a new program, the specialisation is built from the `Info` that translation fills: resource lists plus the SRT walker (vk_pipeline_cache.cpp:1003-1005; specialization.h:119-155 iterates `info->buffers/images/...`). The persisted `Info` includes `PersistentSrtInfo` with **host machine code for the walker** (`walker_func`, vk_pipeline_serialization.cpp:437-456).

Practical key for a cold lookup [I]:
- `shader_hash` → the `Info` template (lets the specialisation be computed without translating).
- `(shader_hash, spec digest)` → SPIR-V.

**The existing on-disk store** (BB_PIPELINE_CACHE, default ON, emulator_settings.h:61; loose files, archive mode off at :60) [C]:
- Directory: `GetUserPath(CacheDir)/<GameSerial>/` (cache_storage.cpp:113-116).

## (3) Loader design (proposal, [I], built on the code read)

Rather than consume offline_xlat's per-program SPIR-V directly (wrong translator, wrong Profile, no specialisation, no Info), use the offline corpus as a list of programs and variants to pre-compile into bbport's own store format.

**a. Producer (offline or first boot).** A headless bbport tool links the vendored `shader_recompiler` and runs it over `estate-extract programs/*.bin`. Inputs:
- The seat's Profile: dumped once from `cache/<serial>/profile.bin`, which is a memcpy of the struct (vk_pipeline_serialization.cpp:323-326).
- RuntimeInfo from HEADERS.tsv, with render-target formats and image number formats enumerated from what the seat has already recorded (the `.meta` spec blobs).

Output, per program: Info (incl. SRT walker) once, plus one SPIR-V per spec digest.

**b. Store.** A content-keyed directory next to the existing one: `CacheDir/<serial>/pre/<shader_hash>/info.bin` and `<spec_digest>.spv`. The header records the translator version (ShaderBinaryVersion), the Profile digest and the bbport patch-series hash. Any mismatch disables the store; it is not cleared.

**c. Lookup, lazy, on the GPU thread's miss paths only:**
- `GetProgram`, new program (vk_pipeline_cache.cpp:1000-1018): look up `info.bin` by `params.hash`. With it, build the spec without translating (the constructor needs only Info, RuntimeInfo, Profile and start; specialization.h:97-168), then look up `<spec_digest>.spv` and call `CompileSPV` only (the vkCreateShaderModule path, as LoadPipelineStage does at vk_pipeline_serialization.cpp:281).
- New permutation (vk_pipeline_cache.cpp:1045-1051): look up the same way.
- Fallback on any miss: the existing `CompileModule`. Write the result back to the store so the next boot hits.
- Startup cost: a directory index only (map of shader_hash to path). The ~26k programs are not loaded eagerly; a 488 MB estate is too much [R: SHADER_TO_PKG_HANDOFF.md:23].

**d. Pipelines:**
- Keep WarmUp's `.key` preload. **Fix its index fragility**: store the spec digest instead of `perm_idx` in the key file and map it to the in-process index when loading, so a different traversal order no longer refuses preloads (vk_pipeline_serialization.cpp:284-296).
- Persist the VkPipelineCache: `vk::PipelineCacheCreateInfo{initialData}` from `CacheDir/<serial>/vk_pipeline_cache.bin` at vk_pipeline_cache.cpp:352. Save it with `getPipelineCacheData` in `Sync()`/the destructor (vk_pipeline_serialization.cpp:391-393). Validate against the Vulkan pipeline cache header (vendor, device, UUID).
- Pipeline libraries and shader objects (plan line 172) are a separate later cut [U]: whether the seat's RADV exposes them was not read here.

**e. Motion-vector VS.** These always compile today (vk_pipeline_serialization.cpp:118-122). To reach zero compiles, the per-session addresses must move out of the SPIR-V (push constant or descriptor), or the check must exclude them explicitly. Whether `positions_address` is non-zero in the native client's default configuration is [U].

**f. Interaction with steps 2-4.** `PreparedDraw` keys on `stage_hashes` = `HashCombine(pgm_hash, perm_idx)` (vk_pipeline_cache.cpp:415, 475-485), which is valid only within one process.      - `NoteStageBRead` of the index range;
     - `Commit` + `FlushStageBReads`.
8. CE side: the CE coroutine runs only when the DE resumes it, at WaitOnCeCounter (1379-1383) and at the end of the buffer (1424-1427).
   - CE packets: WriteConstRam fills `constants_heap` from inline data (423-427). DumpConstRam memcpys heap → guest destination, after the ordering waits (429-470). IncrementCeCounter (472-475). WaitOnDeCounterDiff (477-515).
   - DE packets: IncrementDeCounter records `de_positions` (1373-1377).
   - Note [I]: at 479, `(de_count - ce_count) >= diff` is unsigned and CE ≥ DE (liverpool.h:255). As read, the CE waits until DE equals CE whatever `diff` is.

**Made redundant by a record** (span verified contiguous, section 2):
- the packet-by-packet apply and `HashRegisterPacket`, replaced by one block copy of the record's delta;
- `KeyRegsHash` in Lookup;
- per-stage `GetParams` and the user-data memcmp (sampled instead);
- the flat assign (reference the record);
- `graphics_pipelines.find`, if the record caches the resolved `GraphicsPipeline*`;
- the per-packet `ProcessCommands`, `PipelinedOpcode` check and switch (once per span instead).

**Must still execute, in stream order:**
- WaitOnCeCounter and IncrementDeCounter. Without them the CE is not resumed, so dumps for uncovered draws arrive at the end of the buffer.
- WriteData (1258-1277: `RunInOrder` + `NotePendingWrite` / `NotePendingGpuWrite`).
- EventWriteEop / EventWriteEos (1217-1235).
- EventWrite ZpassDone, which writes guest memory (1204-1213).
- DmaData (1236-1256).
- WaitRegMem (1314-1357).
- PatchedFlip NOP; MemSemaphore (1288-1299); Rewind (1304-1313).
- The CB/DB extent sniffs; SetShReg in the compute range; SetBase.
- The draw packet's own register effect (609-639). Replay stops before `e.packet` (vk_draw_prep.cpp:1095), so the record's state excludes it.
- Then `CollectRingBindings`, `NoteStageBRead` and `Commit` in `PostDraw`, which still read guest memory (Tier 2 removes them).

**Not coverable** (the span decodes normally): IndirectBuffer (Replay does not descend, 753-761), CondExec (1402-1414), DispatchDirect / DispatchIndirect, register-space WaitRegMem, and any unknown opcode.

### 2. Skip design [I], built on what exists
**Record gains** (all produced on the engine thread; Replay already walks the span, 753-761):
- `de_prev`, from `BbEngineEmit.de_prev` (bbgpu.h:43).
- A `RegDelta` of the span. Pass a `RegDirty*` to `ApplyGraphicsRegisterPacket` in Replay (the signature allows it, liverpool.h:92-93). Capture with regs.h:226-242 from `S.regs`; apply with regs.h:244-252.
- A skippable bit: every packet is either a pure register packet or an in-place packet from section 1.
- A 32-bit hash of the span's packet headers plus first payload dword (the register offset).
- The draw packet's dwords (opcode, count, index base or offset, initiator).
- Optionally the resolved `GraphicsPipeline*`.

**Decoder, at the start of each span** (the cursor just past a draw):
1. Walk the span reading headers only: classify each packet, collect in-place packet offsets, keep the header hash. Stop at the first draw opcode.
2. At the draw, check `header[-2] == 0xC0001000` and `header[-1] >> 24 == 0xD1` (vk_draw_prep.cpp:1225-1226). Fetch the record by its 24-bit serial: serial and packet match (1233), lap guard (1237).
3. Accept the skip only if all of these hold:
   - Ready and Use mode;
   - the skippable bit is set;
   - `r.de_prev` equals the previous draw packet this decoder executed in this buffer (contiguity: the shadow replayed exactly these bytes);
   - the header hash matches;
   - the draw dwords match.
4. **Skip path:**
   - one `ProcessCommands()`;
   - run the in-place packets in order through their existing cases (they read packet bytes, not `Regs`);
   - `RegDelta::Apply` into `liverpool->regs` and OR its blocks into `pipe_dirty`, so `PostDraw` ships them (582-656);
   - apply the draw packet's own registers;
   - `Draw(is_indexed, offset, nullptr, record)`.
5. **Otherwise:** decode the span normally from its start. Nothing has executed yet, because the walk is read-only, so nothing runs twice.

**Re-sync rule.** The decoder's `Regs` stay valid without any extra step:
- Each skipped span ends with the shadow's blocks for every block the span touched.
- The shadow equals the decoder at span start by induction: it was seeded from decoder regs (vk_draw_prep.cpp:1248-1257, applied at 1086-1089), and every span since was replayed contiguously, including spans that fell back.
- On any sampled mismatch (section 3): mark the shadow unseeded, so the existing seed post re-arms it, and skip nothing for that object until a new seed lands (the engine is up to a frame ahead, 1245).
- Contiguity fails at the first draw of each buffer and after a chunk switch (`flags & 1`). Those spans decode normally.

**Hazards:**
- `gfx_reg_checksum` stops advancing. `TryPreparedPipeline`'s check (vk_pipeline_cache.cpp:386) holds only because Lookup stamps the current value (1269). The speculative worker path must stay off.
- `IsCopyGpuBuffers` must stay off: copied DCBs break the packet-address key (1233; liverpool.cpp:1775-1777).
- Stage B must not dereference record memory unless the ring slot is pinned until the pipe passes it. The ring is 32,768 entries with a 4,096 lap guard (549-550), and nothing bounds stage-B lag against it.

**Unknown:** the opcode census inside real spans. Have Emit count opcodes per span in compare mode before choosing the in-place set. `BB_DCB_STATS` counts only the packets before the first draw (723-731).

### 3. Version check at decode time
- **Every covered draw (nearly free):**
  - marker tag, 24-bit serial and packet address (1225-1236);
  - `r.de_prev` contiguity;
  - the header hash, computed during the walk anyway;
  - the draw dwords;
  - the lap guard.
  - These catch DE-ring reuse after emit and a misattributed record.
- **Sampled, 1 in 64 per object, plus the first covered span after any fallback, switch or seed:** decode the span fully into a scratch copy of the pre-span decoder regs (taken before the walk).
  - memcmp the touched blocks against the record's delta. This catches shadow drift.
  - Then run the existing cross-check: `RefreshFlatBuf` plus key compare (vk_pipeline_cache.cpp:431-491) and the per-stage `GetParams` hash (414-417). This catches stale shader memory.
  - For each record redirect of kind 0 (dump): after the CE has run its dump, memcmp the arena bytes against the guest destination. This is the dump-class version check of REV2 §7.
- **Rate.** Raise the rate to every draw for N frames after any mismatch. Back off to 1 in 64 only after a clean window.

### 4. CE dump copies on the engine thread
- **In place at emit time: no [I].**
  - Destinations are reused under the game's counter discipline: a dump may reuse memory once WaitOnDeCounterDiff has seen the older groups done (liverpool.cpp:433-436, 490-495).
  - The decoder runs up to a frame behind the engine (vk_draw_prep.cpp:1245). An emit-time write would overwrite a slot that undecoded earlier draws still read. Those reads are `RefreshFlatBuf` and the ring copy on stage A, and buffer reads on stage B, which patch group 16 tracks (liverpool.cpp:445-456).
  - The Carry note (vk_draw_prep.cpp:571-573) states the deferral this depends on.
  - **Unknown [U]:** the real reuse interval of dump destinations against `diff`. Log per-destination repeat distance in trace E (892) to confirm it.
- **What works today:** the engine copies the dumps into the record (`AddCeDumps` 765-780, backing → arena) and redirects the SRT walk (1129-1175). That is the emit-time dump, kept private.
  - The equality it assumes: backing at emit equals WriteConstRam inline data at CE time (comment 763-764, heap fill 423-427). The compare-mode kinds 4/5 test it.
- **Ordering:**
  - (a) The GPU-thread CE dump stays, for uncovered draws, for the 1-in-64 cross-check, and for any V# pointing into dump memory that `CollectRingBindings` or stage B read.
  - (b) The counter-rule wait shrinks on its own once covered draws read the arena instead of guest memory: no `NoteStageBRead` is registered for them, so `StageBReadPosition` finds nothing to wait for (449-456).
  - (c) Retire the GPU-side dump for a destination range only when every reader of that range is covered, and only after the section 3 dump compare has run clean.

### 5. Step 10: vblank, `BB_FPS_LIMIT` and the game's waits
- **D1 has no vblank consumer [C].** It imports no WaitVblank, AddVblankEvent or GetVblankStatus. Its videoout imports are GetFlipStatus, SetFlipRate, AddFlipEvent, IsFlipPending, RegisterBuffers, Open, Close and two color calls (docs/destiny-imports.tsv:358-367).
  - So `vblank_status.count`, the vblank events and `vblank_cv` (driver.cpp:816-838; video_out.cpp:391-400) are not visible to the game. `BB_VBLANK_HZ` cannot speed up or slow the game's clock, as far as these two files show. Other modules: [U].
- **Present loop [C].**
  - `frame_limit != 0` turns on immediate flips (781). These happen only when `flip_rate == 0` (840). SetFlipRate stores 1 → 0 unless `D1_FLIP_RATE=stock` (video_out.cpp:151-160).
  - In that mode, requests are popped between ticks as they arrive (844-865), spaced by `next_flip` (799-801, 852-861). Each request is popped exactly once (`receive_request` 769-777), so there is no double flip.
  - The vblank rate then only sets the wake cadence and the realtime hint (752-758). The 7.1 jump from 43–48 to 56–58 came with `BB_FPS_LIMIT` turning immediate flips on, not from 480 Hz itself [I]. Recheck with `BB_VBLANK_HZ=60 BB_FPS_LIMIT=1000` to confirm.
- **What throttles the game once the deadline is gone:**
  - (a) `PrepareFrame` blocks the GPU thread when the frame pool, which has swapchain-image-count frames, is empty (vk_presenter.cpp:189-200, 779-794; `pool_wait` stat at driver.cpp:565). This is honest back-pressure.
  - (b) The VO label `WaitRegMem` at the head of each buffer. ReleaseAtSubmit clears the previous buffer's label when the next flip is queued (driver.cpp:727-731), so it barely throttles.
  - (c) Flip events and `GetFlipStatus` advance once per Flip (603, 615-624), at present-thread time, not at swap. The swap runs on bb:Present (79-110; Flip 302-307). If D1 times anything off flip events, it sees the present-thread rate. [U]: whether it does.
- **Starvation and overflow risk.** `SubmitFlip` refuses more than 16 pending (686-688), and an EOP flip then asserts (video_out.cpp:372-373). (a) bounds flips in flight to the image count, so this is unreachable while that count is under 16 [I]. Keep `BB_FPS_LIMIT` above the reachable rate: a low limit with no deadline grows the request queue until (a) blocks.
- **Present mode.** Mailbox comes from the `GetPresentMode` setting; FIFO is the fallback when unsupported (vk_swapchain.cpp:201-220). The configured default is [U]. FIFO would put back a 60 Hz quantizer on the swap thread.
- **Order** (PLAN:253): land 10(b), the wall-credit gate at `0x59395a`, before removing the 16,683 µs deadline (CFG+0x28 per d1-outer-wake-5994.md:5-6).
  - With the gate holding, extra outer passes are zero-advance frames. The simulation does not double-step, but they still render and present: same image unless the engine interpolates [U].
  - Without the gate, the fixed domain follows the outer rate (A5: 36.10/s fixed = outer, d1-outer-wake-5994.md:24-28).
  - Discrepancy to settle: that doc's scalar is 1/30 (`0x3d088889`, line 26), while PLAN:241 says `h` = 1/60.
