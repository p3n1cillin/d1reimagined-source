# Charm's Tiger library on build 56578 (1 November 2026)

[Charm](https://github.com/MontagueM/Charm), by MontagueM (GPL-3.0), is a Tiger-engine datamining
tool. Its `Tiger` library has a Destiny 1 strategy (`DESTINY1_RISE_OF_IRON = 1000`, packages prefixed
`ps4`). That strategy reads our PS4 build 56578 packages, but only after a one-line fix.
[`tools/charm_probe`](../tools/charm_probe/README.md) drives it from the command line, without
Charm's window.

## What it reads

The probe opened all 2,105 packages in about 14 s and the investment data in about 9 s more. It
wrote three tables, which stay outside the repository:

| Output | Contents |
| --- | --- |
| `named-tags.tsv` | 643 named tags, including: 279 map, ambient and activity names (class `BA088080`, e.g. `mission_touchdown`); 168 `<activity>:scenario_client`; 122 spaceflight; 57 activity roots (`2E058080`); 11 UI packages (`ui_menus`, `ui_orbit`, `ui_social` …); `investment_globals` and `investment_assets`. |
| `activities-bubbles.tsv` | All 57 activity roots parsed, with no failures. Each has its bubbles and child-map tags; bubble names are string hashes because the global string cache wasn't loaded. |
| `inventory-items.tsv` | 8,609 inventory items, each with the public 32-bit item hash and its English name. 276 names are blank. |

Every item hash in [`ps4/loadouts`](../ps4/loadouts) is in that table: 40 hashes across the four
files, all named (e.g. Gjallarhorn, Fatebringer, Bladedancer). The table can therefore check
equipping, vendor stock and grants on the server against what the build actually contains.

Charm reads these D1 investment roots from hardcoded tags in `Tiger/Schema/Investment/InvestmentHandler.cs`
(`BEFFA580` item map, `9CFFA580` item strings, `27E2A580` talent grids, `49E2A580` dyes). All of them
resolved on 56578.

What it doesn't do for D1: vendors, progressions, unlock flags, objectives, stats and lore return
early. Vendor and unlock definitions still have to be decoded by us, starting from the
`investment_globals` / `investment_assets` named tags, with Tiger as the reader.

## The fix

Upstream commit `50d36ee` (28 December 2024) crashes when it starts the D1 strategy. In
`Tiger/SchemaDeserializer.cs`, `GetStrategyFields` dereferences a null attribute on any field whose
`[SchemaField]` attributes are all for Destiny 2 strategies; about 60 such fields exist, e.g.
`SActivity_WQ` and `STerrain`. [`patches/charm-d1-strategy-null-guard.patch`](../patches/charm-d1-strategy-null-guard.patch)
adds the guard. `CharmProbe --scan` lists the affected fields.

## Building

- **.NET:** the .NET 7 SDK, installed portably with Microsoft's `dotnet-install.ps1`, at `F:\d1\tools\dotnet`.
  Set `NUGET_PACKAGES` and `DOTNET_CLI_HOME` to keep packages off C:.
- **Atlas:** Charm's `Charm.csproj` also needs its C++ `Atlas.dll`. That project hardcodes Windows
  SDK 10.0.22621; [`atlas-override.props`](../tools/charm_probe/atlas-override.props) (passed as
  `ForceImportAfterCppTargets`) relinks it against the installed SDK. The probe needs only `Tiger`,
  not Atlas.
- **Oodle:** Charm ships `oo2core_3_win64.dll` in its `ThirdParty` folder, and the probe copies it
  next to itself.
