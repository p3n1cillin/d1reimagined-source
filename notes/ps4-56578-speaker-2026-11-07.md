# PS4 56578: The Speaker plays, and more places reached (7 November 2026)

The Speaker (activity 167, world `cine_speaker`) played start to finish from our servers in run spk3.
It is the second cinematic to do so, after the reveal ([cine-live13](ps4-56578-cine-live13-2026-11-05.md)).

## How it was served

- **The launcher:** `tools/ps4_setup/d1-full-game.ps1` (the full-game host has the `cine_speaker` world)
  with two overrides:
  - `server:D1_AH_ACTIVITY_REMAP=164:167`: A Guardian Rises' launch is published as 167, so no route
    is needed.
  - `server:D1_AH_SCRIPTS=0`: the script bridge off.
- **The watcher:** `d1-cine-watch.py` stepped the cinematic record as the live host did. It finds the
  host log under `contained-boot/*-NAME`, so the run's `boot` folder was junctioned there:

  ```
  d1-cine-watch.py spk3 --control <run>/ah-control.txt --activity 167 --slice 1 --start-after 20 \
      --states cine_speaker-phase-1.txt cine_speaker-play.txt+1 cine_speaker-done.txt cine_speaker-end.txt+1
  ```

## What did not work

- **spk1, the script bridge on:** the client loaded `cine_speaker` and its region (PRV01.01, the
  transition completed), then stayed on the loading UI. The bridge's `cine_speaker` scripts are a
  start-only stub. The watcher's lists were applied, but no 2681 came, and the client dropped the
  host after about ten minutes.
- **spk2, `d1-agr-run.ps1` with `world-table-speaker-live.txt`:** the older workspace host refused it:
  `world "cine_speaker" has no captured scenario record`.
- **awk1, The Awoken (186), served the same way as spk3:** the client refused the world transition:
  `Activity 'HASH(0x9a7acc78)' index '186' is lacking permissions -- world-transition not allowed`
  (`activity_failed_to_load_missing_permissions`). It came right after the ownership manager's
  "purchased offers" reply. That reply is not the gate. Ours is header-only, and the live A Guardian
  Rises capture's reply is byte-identical (`00160000000d00c8`); that player then played The Awoken.
  `activity-rules.tsv` gives 186 as NOT f3392, NOT f309, f2668, and we serve 2668 and neither of the
  others. The suspects left:
  - the Reef destination's own rule (place `0x95c17d0f`);
  - a local PS4 entitlement (the ownership manager enumerates local entitlements first).

## Repeats and more places (7 November afternoon)

- **The Speaker again.** It played again in spk5 with the same recipe (2681 20 s after phase 1), so it is
  repeatable.
- **Restoration (166), run rst2.** The setup:
  - the full-game host with the script bridge and public instances;
  - `D1_AH_ACTIVITY_REMAP=164:166`;
  - the new tutorial character, which launches 164 by itself (a geared character goes to orbit and
    never launches 164, run rst1).

  What happened: no public session answered for 10 s, so the host started one for region 56 (and one
  for 48). The client reached `activity:in_world` and `player_spawned_initial`. The frames show the
  Steppes rocketyard and the first objective. On 2 November this mission stalled on its public bubble.
  The bridge logs `script squad field "carried" has no 56578 encoding yet`.
- **Orbit and the Director by pad.** This was after the Speaker, in spk5:
  - Orbit shows notices, dismissed with Cross: Shaxx's Crucible unlock, Armsday, Age of Triumph,
    "Venus revealed". The Destiny 2 pre-order panel has Pre-order buttons, so dismiss it with Circle.
  - "Set Destination" is an on-screen button: move the cursor with the left stick, then press Cross.
  - The Director shows the Solar System, then Earth.
  - Some nodes refuse:
    - The Taken King's "Hangar Stakes" says "Requirements Not Met";
    - The Silent Fang (House of Wolves) says "Requires Better Gear".
  - **The Dark Within** launched from it: "Launching in 0:00", about 24 s of black, then in world at
    Devil's Spire.
- **F48, the ship flight.** For the Director launch, the client logged `Activity is NOT matchmade --
  using the cinematic UI`, so it chose the flight. The screen was still black throughout. There are no
  AvPlayer or Bink calls, so the flight is drawn in-engine, and probably rendered black (F47's family).

  The `loading cinematics are suppressed -- using the common loading UI` lines come from launches
  straight from character select. There, `FUN_00766750` is true:
  `*(u8*)*DAT_026bc068 == 1 || FUN_0078c710()`. `lab/tower-route/probe-cine-suppress-readonly.py`
  read the byte at 1 during that load and 0 otherwise.
- **F57, a headless Titan.** In spk3's Speaker cinematic our Titan had no head. Every tutorial and
  geared peer card has the wear-helmet byte (+0x38) at 0. The spk6 run, with it set by
  `d1-character-fixup.py peer --helmet`, did not catch the same shot, so this is still open.
