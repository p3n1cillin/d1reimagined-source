# PS4 56578: a level-1 tutorial Guardian (2 November 2026)

Retail A Guardian Rises is played by a new level-1 character in starter gear. The lab serves
level 40 / Light 385 from the start. `tools/ps4_setup/d1-level1-fixtures.py` builds a level-1 copy
of every object the tutorial route serves. Only level, Light and item level change; Defense and
Attack change too, because they follow from item level through the client's own curves.
Served on 3 November (below).

## What it changes

| Output | Field changes |
|---|---|
| `inventory-tutorial-l1/` (10 items), `grants-l1/khvostov-3598.bin` | +0x18 item level 40 → 1 |
| `profile-tutorial-t-l1.bin`, `grants-l1/profile-tutorial-th.bin` | +0x6FE4 Light override 385 → 5 (the flag at +0x6FDC and the key at +0x6FE0 are unchanged) |
| f0t1 peer cards (`rosters-f0-tutorial-l1/`, `grants-l1/rosters-f0-tutorial-khv/`) | +0x30 level 40 → 1, +0x38 f32 40.0 → 1.0, +0x83C Light 385 → 5 |
| f2t1 cards | +0x10 level 40 → 1, +0x14 Light 385 → 5 (XP +0x18 stays 0, level 1 on the XP curve) |
| `roster-def-l1/` f0t1 (from `roster-def1200-helm-saint14`) | as above, and Defense +0x844 1200 → 30, Attack +0x8BC 200 → 5 |
| f0t0 / f2t0 | copied unchanged |

Every edited object goes through the client's codec: decode, edit, encode (the encoder must
report IDENTICAL), then decode again. The result must equal the edit and differ from the source
only at the listed fields. All 25 objects passed (checks/report.json).

## Derived and assumed

- **Attack 5, derived.** `d1-oracle character derived-stat` gives the Khvostov at item level 1 one
  contribution of 5, matching the manifest's Attack 5.
- **Defense 30, derived.** Six served pieces give 5 each at item level 1: gauntlets, chest, legs,
  class item, Ghost and artifact. The helmet (6514) gives nothing.
  - The control: the same commands on the level-40 objects give the served 1200 and 200.
  - The helm-saint14 card names helmet 1065 (Saint-14) where the inventory serves 6514. That
    helmet would make it 70.
- **Light 5, assumed.** The client's Light aggregation over the equipped items (`0x2660E0` →
  `0x265EF0`) is not decoded, and `derived-stat` refuses Light on purpose.
  - 5 is what every contributing item derives at item level 1, and the mission's own banner says
    "Recommended Light 5".
  - If empty slots count as zero, retail shows less. That needs a retail level-1 character screen
    or the aggregation decoded.

### Or let the client compute Light

With the profile's override present, the client returns its value verbatim and never reads the
equipped items (ps4/design/items-and-gear.md section 10). `--light-native` clears the override
(+0x6FDC 1 → 0) in both profiles instead of setting 5. The client then sums Light over the level-1
gear itself: 1:1, with no number of ours. The cards' stored Light (orbit nameplate, character
select) stays 5. Whether the in-world sum is right, or 0 for want of data, is the first thing to
check in game.

## Serving it

`ending-run.ps1 -ExtraEnv` is appended last, so its values win (Start-D1ContainedBoot.ps1). With
`L=<staging>\level1-test`:

```
-ExtraEnv "D1_PROFILE_FILE=$L\profile-tutorial-t-l1.bin,D1_ROSTER_DIR=$L\rosters-f0-tutorial-l1,D1_INVENTORY=$L\inventory-tutorial-l1,D1_LOOT_GRANT=0x827dbaf0=0xd100000000000401:$L\grants-l1\khvostov-3598.bin|$L\grants-l1\profile-tutorial-th.bin,D1_LOOT_GRANT_ROSTER=$L\roster-def-l1"
```
