## 6. The PPU hook caveat (read before trusting any D1P count)

The transferred `rpcs3.exe` (prefix `d1p2`) logs a hook **before** RPCS3's status check, so
scheduler retries can log the same pre-execution state many times and exhaust a watch budget
without the guest running (RUN_GATE2: 60 records in 12.6 ms). Hook addresses are compiled
partition starts, which can be inside a guest function; zero hits at an arbitrary instruction
proves nothing. The fixed hook is the staged patch (`d1p3`). The main PC built it from that
exact staged patch on 2026-10-01 01:20 (0 errors; binary contains `kusa-d1p3`, no `d1p2`) and
staged it as `rpcs3.d1p3.exe` in both `<D1_ROOT>\main-pc-import\d1xenia\local\RPCS3_FINAL124_SMOKE001`
and `...\RPCS3_TEST048_SETUP` (SHA-256 `6a79e3e758d062afd6512d4766901280b29e4f869e7f9b1b9500fb883930702f`).
Swap it in by renaming when no emulator runs (keep the old exe as `rpcs3.d1p2.exe`). `d1p3`
forces a full PPU recompile on first boot (20-40 min, black window): do one warm-up boot without
the login timeout. The main PC's `C:\dev\rpcs3` tree now holds that patch, not the `d1p2` one.

## 9. Dead ends - do not repeat

- Answering 01.24 STUN with more reply shapes before identifying what stage 19 waits on (8 shapes,
  identical results).
- Trusting pre-admission D1P counts or mid-function hook addresses (see 6).
- Mid-session host type-11 world-state deltas to move a 01.00 client between bubbles (not
  applied in the world; TEST366-368 context).
- Stepping kind-4 objects as a "cinematic trigger" (it is a respawn counter).
- Copying a GPU's Vulkan pipeline cache to another GPU.
- `u`-mode hook dedup on the first bytes of a message whose differing field is deep inside it.
