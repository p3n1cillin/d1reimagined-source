## Authority in scheduled mission steps

The run-11 authority override was read only by live `clients GROUP PATH`
commands. World-table and mission-step lists silently discarded the same
`@authority` header, so putting the working Divide list behind `%96|900`
would still build a frame with the launch machine (3).

All three paths now use one list reader. A list can carry
`@authority MACHINE[,SEQ[,APPLIED]]`; omitted sequence/applied fields mean
`1`/`1`, and no header preserves the launch authority. Inline comments are
allowed. Duplicate headers, empty fields, out-of-range machine/sequence
values and applied values other than `0`/`1` fail with the list and line
identified. Both team variants retain the override; lifetime generation,
phase, tail and duplicate-record filtering retain their existing behavior.

## Member binding crash corrected; authored Divide squads identified

The run-12 member activation crash has a concrete cause. The member state
`0x80800868` contains an optional object reference at **+0x50** and an index at
**+0x58**. The state callback at `0x1BCEC3..0x1BCF34` caches them when the
reference is present and the index is not -1. Its later lookup at `0x1BDCC1`
assumes that binding resolves. All-zero bytes mean a present reference and
index 0; they are not the absent default.

`tools/ps4_setup/d1-member-states.py` builds the diagnostic activation with
`{0x811C9DC5, 0xFF, 0xFFFF}` at +0x50 and index -1 at +0x58. It preserves the
list's authority, other clients and existing B images. In run 14, member 21
alone survived first, followed by all six authored members (5, 7, 9, 11, 13,
21). All six were read back with generation 1 and the corrected absent
binding, with repeated updates and more than ten minutes without the earlier
crash. The source tool generated the same A images and its output was then
published successfully. **This fixes the tested invalid-binding crash; it
does not establish the full encounter or correct flight paths.**
