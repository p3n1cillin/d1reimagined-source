# PS4 56578: the Ghost in the palm (F54) and the activity option that blocks it (8 November 2026)

When our Guardian has no weapon equipped, the first-person view shows the Ghost hovering over the
open palm. This happens in A Guardian Rises until the rifle, and in Restoration and The Dark Within
with the tutorial character. The launch footage shows no hands in that stretch. Two read-only
passes over the 56578 executable (Ghidra) traced the client side and the server's way in. No code
changed; nothing below has been tried in a run yet.

## How the Ghost gets into the hand

- **Every Ghost spawn passes `0x741af0`.** It refuses when:
  - the unit is not locally owned;
  - the unit's Ghost template (`+0x1210`) is -1. It is copied from the gear blob `+0x324` in
    `0x73fd50`, probably the equipped shell;
  - the **activity option `0xB3C6F690`** is set and true.
- **Into the hand: `0x742820`.** With equipment slot 3 empty, it spawns the Ghost, attaches it to
  slot 3 and sets Ghost state `+0x2a8` = 1. Two callers:
  - the `ghost_deploy` action's start `0x379980`, when the action definition's `+0x1c` flag is set.
    Content decides when this action runs;
  - `ghost_summon`'s update `0x37c050`, only after a touchpad press. Its chain is `+0x1418` ←
    `0x744990` ← the CUI deterministic globals `0x9828d0` ← `0xabab40` ← the touchpad state
    `0xabae10`.
- **The light-volume Ghost: `0x741690`.** It floats in light volumes (state 9). Option
  `0x0150F05D` blocks it. Option `0x0AA3660F` is read in the weapon refresh `0x5a5320`; its meaning
  is unknown.

No code rule turns "no weapon equipped" into the deploy. That rule is most likely the player's
action content. So the 1:1 lever is the option: with `0xB3C6F690` true, no Ghost object can
spawn at all.

## Where the option comes from

- **The table.** The lookup `0x118870` reads the activity game system's "Activity Options Game
  State" table (`c_activity_game_system` at `0x26ae458`). Its manager (`singleton+0x18`, slot
  `+0x40` = `0x3d95f0`) returns the table.
- **Its one writer: `0x417b00`, at activity start** (slot 2, `0x417810`). It merges, later entries
  replacing earlier ones:
  - content options: the activity tag's list `+0x128`, conditional option tags, the global tag's
    list, per-slot bools;
  - **the game options list:** count at `+0x12fc`, 50 entries of 24 bytes at `+0x1300`.
- **`0xB3C6F690` can only come from the game options list.** It occurs once in the executable, at
  its store `0x743dc2`, and in no exported activity-options tag. No mission-script built-in sets an
  option.
- **The game options list comes from the server's udt 1 `global_activity_state`** (`0x80800E76`,
  inner `0x80800B8F`). Its blob `+0x60` is `0x80800CC5`, whose `+4` is the list `0x8080533D`: a
  6-bit count at blob `+0x64`, then 50 × 24-byte `0x80800D17` entries at `+0x68`, each a u32 name
  hash and a typed value.
- **It is copied once.** `0x7a9880` copies it at `setup:activity_world_transition` (`0x7a8dd0`;
  "Unable to get world options from the activity client options" if missing). `0x754c20` then
  copies it into game options, and game start `0x906530` copies it into the game globals that
  `0x417b00` reads. **So the option must already be in udt 1 when the client starts the world
  transition into the activity.** Sending it later does nothing until the next activity start.

This also answers the Crucible note's open question
([crucible wire](ps4-56578-crucible-wire-2026-11-06.md)): the manager's table is built from the
global activity state's list, not from the lifetime row.

## What stands between us and sending it

- **Our crate refuses a non-empty list on purpose** (`messages.rs`, `GlobalActivityState`). The
  codec cannot encode the entries' typed value yet: kind `0x29`, whose wire tag for a bool (and for
  an int: `score_to_win`) is not bound. `d1_oracle::sensor::TYPED_VALUE_TYPES` knows only
  `0x8080279A` and `0x80801732`. In memory the bool type is the cell `*(u32*)0x28db450`.
- **The live captures can't settle the value.** The 56578 codec does not decode the 360's udt 1,
  and the three option hashes appear nowhere byte-aligned in the 56 captures.
