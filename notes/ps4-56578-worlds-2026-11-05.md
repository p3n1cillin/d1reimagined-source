# PS4 56578: a world for every activity, from the client's own content (5 November 2026)

**Result.** The activity host can now be handed a world for any activity, generated rather than
hand-built: the 224 worlds' scenario facts, their 2,545 slice sets, every bundle's sensor clients
and the insertion points come from the owned 56578 packages, and each of the 653 activities is
bound to its world by the evidence available. Since stream Q (6 November) that includes the
client's own activity table, whose definitions name the world each activity loads: **534 of the 653
activities have a world (290 before): 57 cross-checked against a live host, 477 generated, 119
without one.** Those 119 name no world of this build: 82 playlists (they launch another activity),
the Crucible's Private Match modes, the credits and several cinematics, one unnamed activity, and
two rows naming 2014 bundles 56578 has no scenario for. The full-game profile serves every bound
activity (`D1_AH_WORLDS_ACTIVITIES=all`). Build and unit tests only; nothing was run in the lab.

- Tables: [`ps4/fixtures/56578/worlds/`](../ps4/fixtures/56578/worlds/), format in the
  [fixtures README](../ps4/fixtures/56578/README.md#worlds-the-generated-world-tables).
- Generator: `tools/ps4_setup/d1-worlds.mjs` (content) and `tools/ps4_setup/d1-world-table.py`
  (tables and bindings).
- Host: `D1_AH_WORLDS=<folder>` (`crates/d1-activity-host/src/generated.rs`). Unset = no change.

## What the client's content gives, and what it does not

Read with gibbon, Blam Network's MIT tag reader, whose 56578 definitions match our build:

| Step | Tag | What it gives |
|---|---|---|
| `<world>:scenario_client` (224) | 80800616 | `+0x08` FNV-1 of the world name, `+0x0C` PRIVATE checksum, bubble count, per bubble its states (slice set `8*b+s`): valid, public, region hash, slice descriptor |
| slice descriptor | 808008F0 | the static world (a destination, 35 in all) and bubble, and the client blueprint set |
| client blueprint set | — | the bundle tags the slice set loads: global, authoritative, private |
| activity bundle (1,692 tags, 930 groups) | 8080076E | its sensor group (FNV-1 of the bundle name) and lookup groups per bubble (-1 = all), each row's host definition with its A (auth) and B (sense) value types |
| static world → bubble → placement sets → spawn point sets | 8080052E … 80800500 | the spawn points' name hashes: the insertion points the client picks by the transition name the server sends (else `default`) |

The generated scenario facts match every world the host had measured
([worlds.rs](../ps4/d1-server/crates/d1-activity-host/src/worlds.rs): First Light, orbit and its
eleven choosable bubbles, Twilight Gap's map, the Highway, The Dark Within, the Tower, the hangar,
cine_reveal, cine_speaker, The Awoken).

**The sensor-client rule.** A slice set registers every client of its bundles whose lookup group
names its bubble or every bubble, and that has an A or B value type (rows with neither, such as
firing-area sets, register nothing). That reproduces, record for record including the A/B flags,
every list read from the client's memory: the Tower (set 0, 100 records), cine_reveal (25, 22),
cine_speaker (1, 22), The Dark Within (8, 58) and the Highway (113, 24). First Light's list
(set 0, 96) is reproduced plus its lifetime record (`0xc2dacaf7/0x10/3`), which the host serves
separately. So the host no longer needs a client memory read to know a world's sensor list; it
still needs one, or a capture, for any value other than the default.

**Which world an activity loads: the client's own activity table** (stream Q, 6 November). The
first version of this note said the client's activity definitions name no world. They do. The
activity table (investment globals, one tag of class `80801915`) holds each definition inline: a
tag block of 653 entries `{u32 activity hash, u32 0, i64 pointer}`, and the definition is the 360's
`s_activity_definition` (gibbon's v41375 `activity_definition.ts`) widened to 64 bits. Its `name`
at `+0x58`, a self-relative string, is the activity's bundle name, and that is the world:
`<name>:scenario_client`. `fallback_name` at `+0x60` is `action_mock` on 52 rows. The proof is the
captures: **every one of the 56 activities a live host cross-checks names the world that host
served.** `d1-worlds.mjs` exports the table (index, hash, name); `d1-world-table.py` binds by it.

Of the 653 definitions, 529 name one of the 224 worlds, 5 name a bundle with no scenario in 56578
(`cosmo_patrols_1`, `moon_patrols_1`, `mars_patrols_1` and `venus_patrols_1`, the 2014 patrols the
Taken King's `patrol_*_com01` worlds replaced, and `pvp_arena_fallen`), and 119 name none: the
playlists, the Crucible's modes (a Private Match picks its map), the credits and several
cinematics. The host still publishes the world (`global_activity_state+0x688`); the client's table
says which one it expects.

The evidence, strongest first:

1. **The live captures** (Xbox 360, build 51539; private). `d1-srcp.py hosts` lists every activity
   host's sensor groups and the client's first slice set. The world is the one whose bundles explain
   the groups best, each group weighted by how few worlds have it (647 of the 930 groups belong to
   one world), and which has that slice set. This also gives the start slice set the live host
   used. 57 activities, the Cosmodrome patrol (93) added from the 6 November capture. The Tower
   variant the AGR and Tower captures visited (index 1) fits all six Tower worlds equally. Status
   **cross-checked**. The committed cross-checked rows stand in for the captures when the table is
   regenerated without them (`read_captured`), so `activities.tsv` regenerates byte for byte from
   the owned content alone.
2. **The client's activity table** (above), when the name is a world and the activity is not a
   playlist (a playlist picks one of its entries; Vanguard Legacy's own row names
   `strike_kingpin`). Status **generated**, evidence `client's activity definition names it`. It
   outranks the next two: 60 rows they had bound change world (below).
3. **Blam Network's 2014 activity table** (build 41375, `activities.csv` in tiger's dictionary, a
   local external input): its codename is the world. Only 21 of 56578's activity hashes are
   unchanged since 2014, so it is matched by hash, then by name and description, then by name; a
   cinematic activity type picks the cinematic world among several. It now binds only the rows the
   client's table leaves open (the first Tower row, index 0, whose definition names no world).
4. **Twins.** An activity with the same name and destination as a cross-checked one (heroic, playlist
   and nightfall copies) takes its world, and its captured start, when nothing disagrees. An
   activity whose own definition names a bundle with no scenario takes a twin the client's table
   binds (Patrol the Moon 9, Patrol Venus 10, Patrol Mars 11). Status **generated**.

**Insertion points.** The generator records, per static world bubble, the spawn points' name hashes
(`insertion-points.tsv`). The host does not yet send a transition name, so the client takes
`default`; the table is there for the activity framework. Codex's incident catalogue names 56578
incident 3732 `insertion_point`, but in the captures it accompanies entity handovers (udt 23/24),
not spawns (Codex's catalogue, PR #306).

## Differences from the hand-built tables

- **The Tower starts in slice set 24** (bubble 3, the Plaza) in the generated table: the 2014 start
  bubble and the AGR capture's Tower host both say so. The hand table uses 0, which also worked (run
  sense57). Hand rows win over generated rows, so nothing changes until a run chooses otherwise.
- **`pvp_city_defense` is Twilight Gap** (index 133) in the 2014 table. `worlds.rs` calls it
  Bannerfall, after the map chosen in the menu for run `2026-10-14-citydef`; the client loads the
  world the host names, whatever the menu says. Bannerfall's own world is unbound.
- Private Match modes (410 Skirmish, 416 Elimination ...) have no world: the map is chosen per match.
  The hand table's First Light rows for 410 and 416 stay.

## Using it

```
D1_AH_WORLDS=ps4/fixtures/56578/worlds            # every activity with a world
D1_AH_WORLDS_ACTIVITIES=164,165,167,0             # optional: only these (two frame builds per distinct world and start)
D1_AH_WORLDS_ACTIVITIES=all                       # or every activity with a world, as unset (the full-game profile)
D1_AH_WORLDS_PRIVATE_START=1                      # optional: private stand-in for public starts
```

**What serving every world costs** (`tests/all_worlds.rs`, a debug build on the lab host). With
`all`, main.rs plans the 534 bound activities and builds two udt 5 frames (teams 0 and -1) for each
of the 165 distinct (world, start slice set, group) keys before the host listens. Loading the
tables takes 76 ms, planning 88 ms and the frames' parameters 151 ms; the 330 frames build natively
(`D1_RSAT_NATIVE=1`, no value schema to check, so none falls back to the client's codec) in 204 ms
and hold 426 KiB; the plans' lists add 1.5 MiB. The script bridge's table (below) holds each
world's slice lists once, whichever rows name the world (`SliceRowsCache`); without that sharing
its 473 rows held 1.49 M row entries (about 120 MB) and took 9 s to parse in a debug build; shared,
the 109 worlds' lists hold 364,000 (about 29 MB) and parse in 2.8 s.

The loader skips an activity with no world or no lifetime record in its start set and logs why
(with `D1_AH_WORLDS_ACTIVITIES`). It warns when a generated checksum differs from `worlds.rs`.
`d1-world-table.py --sensor-list cine_reveal:25` prints a generated list in the `mission/` format,
for hand tables and mission steps.

Regenerating (owned packages, Node 22, tiger built; the manifest and the 2014 table local). The
captures are optional: without `--hosts`, the committed cross-checked rows stand in for them, and
with new captures they add to them.

```
node tools/ps4_setup/d1-worlds.mjs <dump>/CUSA00219/packages PRIVATE/worlds.json      # about a minute warm, 8 on a cold disk
python tools/ps4_setup/d1-world-table.py --worlds-json PRIVATE/worlds.json --coverage-md PRIVATE/coverage.md
python tools/ps4_setup/d1-srcp.py hosts <new captures>.pcap --activity-table ps4/fixtures/56578/characters/activity-table.tsv > PRIVATE/hosts.tsv
python tools/ps4_setup/d1-world-table.py --worlds-json PRIVATE/worlds.json --hosts PRIVATE/hosts.tsv     # with new captures
python tools/ps4_setup/d1-scripts-table.py --manifest <DIM manifest> --table-2014 <tiger>/.../activities.csv --scripts <Fukugen Daihon 56578>
```

Tests: `tests/test_world_table.py` (synthetic binding rules, the client's table among them; the
committed tables against the client's lists and the measured worlds, and every cross-checked row
agreeing with the client's table; with `D1_WORLDS_JSON`, a byte-for-byte regeneration of the

`tests/test_d1_worlds.mjs` (`node --test`; the owned packages when present, the activity table
among them), the `generated` module's cargo tests (the committed tables against `KNOWN_WORLDS`,
every plan's list parsing into a sensor frame's clients, a public-only world's start), and
`tests/all_worlds.rs` (what serving every world costs, above).

**The script bridge's table** (`ps4/fixtures/56578/scripts/activities.txt`, stream K's
`d1-scripts-table.py`) now lists every bound PvE activity: story missions, cinematics, quests,
strikes, raids and arenas, 473 rows (138 before). The social spaces, patrols and Crucible maps
stay with the open world, the public host and `pvp.rs`. 250 rows name a world no restored script
starts (King's Fall, Wrath of the Machine, the arenas, most Taken King and Rise of Iron content);
the sidecar serves those as start-only stubs on their content bundles, as the upstream stubs are
(`tools/script-host/PROTOCOL.md`), and the host drives their lifetime.

## Open

- **Values.** Generated lists carry default values. Lists that need served values (the Tower's
  squads, First Light's spawn bundles, mission steps) keep their hand files.
- **Starts.** 235 bound activities start in a stand-in, the world's first private slice set (King's
  Fall, Wrath of the Machine, the arenas, most Rise of Iron missions): no capture or 2014 row gives
  their start. A capture of each, or the scripts' `@start_slice` where a script exists, would.
- **Still unbound** (119): the 82 playlists, the 24 Private Match modes (400-423), 10 credits and
  cinematics whose definitions name no world, `Classified` (129), the unnamed `pvp_arena_fallen`
  row (130) and Patrol Cosmodrome (8), the 2014 patrol row whose `cosmo_patrols_1` has no scenario
  and no twin under its name (the Taken King's is Patrol the Cosmodrome, 93).
- **The Tower variants.** The client's table binds each Tower row to its `city_tower_*` world
  (index 1, the Tower the AGR and Tower captures visited, to `city_tower_default1`). The captures'
  groups fit all six Tower worlds equally, so they cannot cross-check it.
- None of the generated rows has been served in the lab yet.
