# PS4 56578: the Khvostov's sight reticle draws (F53), 12 November 2026

Aiming down the Khvostov's sight showed an empty sight glass: no reticle and no glass overlays.
The hip-fire crosshair was fine. The fix is fork PR
[p3n1cillin/d1reimagined-shadps4#16](https://github.com/p3n1cillin/d1reimagined-shadps4/pull/16),
switched on by `D1_STENCIL_CLEAR_MASK=1` (the full-game profile sets it; the baseline profile clears it).

## How the game draws the reticle (build 56578)

Source: a RenderDoc capture of an aiming frame and a hip frame from run gh38. Analysed offline.

- **Draw:** the reticle is a HUD quad drawn late in the frame. It is 54×54 px at the sight glass
  centre (960, 620) when aiming, and 21×21 px at the hip. An intensity constant is 1.0 aiming and
  0.0 at the hip.
- **Test:** its pixel shader reads the scene's stencil as a texture (a stencil-aspect view of the
  D32S8 scene depth-stencil). It discards the pixel unless stencil bit 0x04 is set.
- **Setting bit 0x04:** the first-person weapon pass clears stencil to 4 (write mask 0xFF, with the
  depth clear). The weapon then clears bit 0x04 where it draws. Bit 0x04 stays set everywhere the
  weapon does not cover, including the view through the sight glass.
- **Glass overlays:** three sight-glass overlay draws test the same bit (compare mask 4).
- **Later clears:** later in the frame the game issues eight stencil clears through
  `DB_RENDER_CONTROL.stencil_clear_enable`. Clear values are 0x10 ×5, 0x00, 0x10, 0x00. Each is one
  3-vertex draw with no colour, stencil op REPLACE, compare ALWAYS.
- **Write mask on those clears:** the game's own stencil write mask is 0x10. The fork's
  stencil-clear logging showed this in run gh40: 28 of the 36 clears logged had mask 0x10, and the
  rest had 0xFF. A clear that honours a 0x10 write mask cannot touch bit 0x04. That hardware does
  honour it was not tested on a console; the in-game result agrees with it.

## What went wrong in the emulator

- Upstream shadPS4 turns every such clear into a full 8-bit attachment clear (load op CLEAR). It
  also forces the draw's stencil write mask to 0.
- The last clear (value 0) wiped bit 0x04. The reticle and the glass overlays were then discarded on
  every pixel.

## What the emulator does with D1_STENCIL_CLEAR_MASK=1

- A guest stencil clear whose front write mask is not 0xFF keeps the attachment (load op LOAD). The
  guest's clear draw then writes `stencil_clear & 0xFF` through the guest's mask. It uses compare
  ALWAYS, ops REPLACE, on both faces.
- All of this is dynamic state. No pipeline key changes.
- A clear with mask 0xFF is still a full clear, as before.
- `D1_STENCIL_CLEAR_LOG=1` (or the main switch) logs the first 64 stencil-clear draws.

## Runs

All runs are A Guardian Rises on build 56578, 12 November 2026.

| run | emulator build | result |
|---|---|---|
| gh38 | fork c80fdb4 | RenderDoc captures, hip and aiming, analysed offline: no reticle. Inferred from the draw trace: the stencil is 0 in the sight window when the reticle draws (last clear value 0, no later stencil writes). |
| gh40 | fork 81edaea, switch on | in game: aiming shows the reticle (a red-white ring with four arcs and a centre circle). The glass overlays were not checked separately. |
| gh41 | fork 81edaea, switch on | in game: 50-minute scripted run, no emulator exception. No visual regression seen in contact sheets of the recording (1 frame per 45 s, checked by eye). |

## Ruled out

- A draw first taken for the reticle (a pipeline with additive particles) is smoke.
- The first hip-versus-aim capture pair was two aiming frames. The comparison was redone.
- No missing texture is involved. The reticle's texture is bound and valid.

## Open

- **Other sights:** only the Khvostov was checked. Other weapons' sights and scopes use the same
  stencil bit by assumption, not by test.
- **Other effects:** whether any other effect relied on the old full clear is not known. None was
  seen in gh41.
- **Lab switch:** the spawn-armed lab switch used to reach the rifle early is
  `D1_LOOT_GRANT_AT_SIGNIN` (#375).
