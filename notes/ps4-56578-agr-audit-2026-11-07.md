# A Guardian Rises activity-host audit, 7 November 2026

[d1-audit.py](../tools/ps4_setup/d1-audit.py) compares local activity-host frame dumps with
live SRCP captures through the existing frame reader and client value decoder. It records
every row, explicit value event, distinct value image, missing tag and decode refusal in a
private JSON report. Byte differences cover the first explicit image, first subsequent
change, last explicit image and every differing change ordinal. Each local run and live
host stays separate. Reports are refused inside this checkout.

The offline audit used the supplied bridge runs and step schedule. The decoder targets
build 56578; the live reference comes from another client version. Matching schema tags
and successful decoding do not establish that every field has the same meaning across
versions. The detailed report and spawn traffic analysis remain outside the repository.

The differences, in mission order:

- **Opening:** squad, actor and machine rows have live explicit values absent from the
  bridge dumps. Object histories differ; the opening trigger image sequences agree in
  the decoded subset. Sequence and cinematic histories also differ.
- **The Breach:** the tripwire object image histories differ from the live reference.
  The bridge supplies a single explicit image where live supplies changes. This is an
  investigation target for the missing beams; this audit does not establish their cause.
  The area objective has a live explicit zero image absent from ours. Squad rows carry
  no explicit values in the supplied local dumps, so the reported squad-default field
  mismatch cannot be confirmed as an emitted byte difference from these inputs. Actor,
  machine, sequence and other object histories differ too. The bridge's Breach trigger
  image sequences agree with the decoded live sequences.
- **The Divide and Dock 13:** live sends area rows and objective initialisation absent
  from these local dumps. Their absence is a capture-coverage limitation: the local runs
  end earlier, so it does not establish what a later local playthrough would send.
- **Mission and world state:** guidance, cinematic, trigger-group, player bundle,
  lifetime, timer, scoreboard and wipe-state histories have missing or differing values.
  Dialogue sequence histories also differ. Playthrough progress, clocks and player
  identity can explain some differences; the report deliberately does not mask them.
- **Spawn context:** the live profile pushes near spawn do not report a current-activity
  change or inventory-slot change through the existing readers. Some profile decoding
  is partial. Local activity-host dumps contain no investment/profile traffic, so they
  cannot establish an inventory or first-person Ghost-state mismatch.

Unknown row tags and refused value decodes remain unresolved, never successful matches.
This audit compares explicit A values; B values, authority and timing remain outside its
scope. Change ordinal is not phase synchronisation, and the last explicit value is not
proof of steady state. No emulator was driven and no in-game behaviour was validated.

Validation: the synthetic audit controls and existing frame/SRCP controls pass. No server
implementation changed; the row encoders and script bridge were left untouched.
